# Color and physical panel boundary

Status: normative.

Spatial resolution and color meaning are independent. A device-native source establishes one source pixel per device pixel under `OneToOne`; it does not establish what its RGB code values mean. Sources of any raster size require an explicit placement policy before panel evaluation.

`Source Adjustment` is the Color-owned extended scene-linear ACEScg boundary between Origin and Feeder Output. It applies explicit exposure, contrast, saturation, temperature and tint while preserving alpha, negatives and values above one. Image-backed incident radiance uses the same operator before physical cd/m² calibration, with a typed incident-radiance policy that compresses chroma toward neutral only when necessary to keep every channel non-negative. It never silently clamps channels. Environment Character remains a separate multiplicative reflection contribution.

An image Environment explicitly selects either a distant latitude-longitude field or a finite sphere with authored world-space center and physical radius. Finite mode intersects each cover-local reflected ray with that sphere before resolving the source direction; translating the center and changing the radius produce geometric parallax rather than scaling radiance or applying a 2D zoom. Validation requires the complete camera aperture and Device to remain strictly inside the sphere.

The current boundary is:

```text
decoded encoded RGB
→ explicit Input Transform
→ linear ACEScg interchange
→ independently authored feeder Output Signal transform
→ nonlinear feeder signal RGB
→ feeder placement into the selected target-device raster
→ explicit Device Color Mode interpretation
→ panel EOTF, black/white levels and channel response
→ physical native-primary subpixel emission and angular response
→ fixed Device-owned panel spatial uniformity
→ calibrated panel light spread
→ resolved camera/screen relative geometry and ideal incidence rays
→ optical-cover transmission and authored environment reflection
→ calibrated VFX emission glow
→ per-emitter lens character and projection with absolute luminance retained
→ explicit native-primary/white-point conversion
→ linear image-plane illuminance in ACEScg
```

The incident-environment port accepts exactly one resolved source: a complete synthetic linear-HDR profile or a decoded equirectangular radiance map already transformed explicitly to ACEScg. Synthetic distributions include the current production and diagnostic patterns. An image source additionally owns its cd/m²-per-linear-unit calibration, exposure in stops and explicit scene-world X/Y rotation; its raster must be finite, 2:1 and present exactly when the stable `environment-image` source is selected. X tilts elevation over -90°..90° and Y rotates longitude over -180°..180°; neither value is inferred from a retired single-angle representation. Distant mode evaluates directions at infinity. Finite mode defines one sphere with an explicitly authored world-space centre; its radius is authored in metres and must strictly enclose the complete camera aperture and every active Device corner. Cover impacts and reflection directions are transformed into scene-world coordinates before intersecting that sphere, so changing centre or radius changes parallax but can never expose an exterior or a black surround. Environment strength zero is exact absence. Nonzero radiance is added only through the cover interface reflection and never modulates or replaces panel emission. Roughness and haze broaden synthetic structure toward its bounded mean. Image-backed reflection is evaluated directly from the exact single-level radiance map with the resolved view direction. The reference evaluator integrates the exact GGX microfacet BRDF with exact unpolarized dielectric Fresnel and Smith masking, without a screen-space blur, radiance mip pyramid or manually stretched halo. The Metal estimator uses balanced multiple-importance sampling between visible Trowbridge-Reitz/GGX normals and a solid-angle-correct luminance distribution prepared from the exact source; every accepted sample reads unchanged level-zero radiance. Oblique highlight shape therefore follows the view-dependent microfacet geometry rather than a fitted circle or ellipse. A deterministic per-output-pixel Cranley shift decorrelates the shared Hammersley sequence without frame noise; Draft, Medium, High and Native use respectively 32, 64, 96 and 128 samples of the same model. Authored zero roughness remains the exact mirror lookup. Haze remains the separately owned bounded transmission/scatter approximation and is not presented as a second GGX roughness. Both environment source kinds enter the same cover-interface response.

The Input Transform and panel EOTF must never linearize the same signal twice. `screen-color` resolves every named Input Transform through the pinned OCIO configuration into linear ACEScg. It classifies that explicit transform as scene-referred, display-referred or the inverse of one named ACES Output Transform. The independently authored feeder `Output Signal` then resolves exactly one OCIO processor. Scene-referred sources use its named display/view processor; display-referred sources use its colorimetric output color space. A source and Output Signal with the same encoding still traverse OCIO through ACEScg in float. There is no identity source-to-feeder route. The Device `Color Mode` never selects or changes this processor: `screen-panel` interprets the already-produced codes through the selected mode's EOTF and converts them into physical emission. Matching Output Signal and Color Mode preserve intended appearance; an intentional mismatch remains executable and changes emission.

The native macOS physical-frame input therefore carries two distinct typed
texture views in one opaque handle: the source linear ACEScg texture used for
identity/bypass, and the nonlinear feeder RGB texture produced by StudioColor
after the explicit Output Signal transform. It also carries the authored
`Fit`, `FillCrop`, `Stretch` or `OneToOne` placement. Feeder composition owns
that placement into the selected target-device raster. The current physical
port evaluates the composed raster without allocating a duplicate full-native
texture, but Panel receives exactly the same typed result and cannot reinterpret
or choose its placement. Screen sampling consumes the prepared Device RGB; it
never derives Device RGB from ACEScg internally.
Capture consumes the physical Screen result. Neither domain may reinterpret
one texture as the other or infer placement from raster dimensions.

## Initial import defaults
<!-- decision-owner: media.unlabeled-import-defaults -->

Media transports declared primaries, transfer characteristic, matrix coefficients, range and alpha presence/association as typed evidence without interpreting them. On initial import of a decodable Source or Reference, Application preserves each unambiguous detected field and materializes only absent fields from one disclosed editable default contract: sRGB encoded Rec.709 Input Transform; Y′CbCr, BT.709 and video range for movies; RGB and full range for stills; Premultiplied for present alpha whose association is absent; Ignore/Opaque when alpha is absent. Every value not supplied unambiguously by metadata remains marked proposed, is listed to the user before decode and becomes the initial explicit authoring rather than detected evidence. This rule never chooses a codec or makes an unsupported codec decodable. A Saved Scene, Queue attempt or already authored Source/Reference is authoritative and never receives these import defaults again. The persisted authored Input Transform and Output Signal are independent and authoritative. Named transforms and Output Signals are stable application identifiers resolved only by `screen-color` against the one bundled OCIO configuration. Device Color Modes and their EOTFs are Panel-owned capabilities. The desktop receives every catalog label and proposal from the owning domain; it does not reproduce OCIO names, EOTFs or color rules. UI calls the source control `Input Transform`, the feeder control `Output Signal`, the screen control `Color Mode` and the independent physical white control `White Luminance`.

A Device preset declares the stable Color Mode identifiers and EOTF interpretations it supports and its calibrated White Luminance capability, including finite minimum, maximum, step and reference value. It does not own or duplicate feeder OCIO processors. The authored simulation instance separately selects one Output Signal, one Device, one supported Color Mode and one in-range White Luminance. Application validates and materializes that selection before Color or Panel evaluation; changing instance authoring never mutates the preset. Presentation receives only the resolved option and scalar descriptors and cannot filter Color Modes or invent luminance bounds.

Feeder owns two consecutive typed artifacts. Its strict color checkpoint contains the nonlinear RGBA16F source raster without display quantization, exact source dimensions, Input Transform id and reference domain, Output Signal id, resolved feeder-output id and resolved alpha interpretation. Device, Color Mode, White Luminance, placement and Preview quality cannot mutate that color checkpoint. Feeder then applies the authored placement against the selected target Device raster and publishes `placed-feeder-signal-v1`; changing Device dimensions or placement therefore changes this phase output without recoding the strict color checkpoint. Device Mapping and Interpretation consumes only the placed artifact. Both comparison evaluators consume the same accepted artifact; diagnostic PNGs are derived views and never become physical inputs. End-to-end evaluation remains separately validated so checkpoint isolation cannot hide an integration error.

Alpha association is an independent authored decision. `Straight` and `Premultiplied` are explicit interpretations; `Ignore` discards alpha for association and treats decoded RGB as unassociated. Initial import alone proposes Premultiplied when alpha is present but its association is absent, or Ignore/Opaque when no alpha exists, and discloses that proposal before decoding. The user may change it immediately and persisted authoring is thereafter authoritative. Before the source color processor, straight RGB remains unassociated and premultiplied RGB is unassociated explicitly; zero-alpha premultiplied samples resolve to zero unassociated RGB. Alpha interpretation never selects an IDT. Feeder placement also publishes the resolved scalar alpha as a non-color sidecar in `placed-feeder-signal-v1`. The separately authored Device VFX Alpha Mode decides whether the physical Device ignores that sidecar or uses it as whole-Device visibility. It never changes RGB association, EOTF or color transforms.

In `device-transparency` mode the sidecar attenuates each Device contribution exactly once at its physical origin: panel emission is attenuated before light spread and emission glow, and reflected/cover contributions use the same authored visibility. Geometry, projection and lens filtering transport a matching occlusion matte alongside the additive linear RGB result. The final `device-vfx-composite-v1` contract is premultiplied additive Device RGB plus an unambiguous occlusion matte, composed as `DeviceRGB + referenceRGB × (1 − matte)`. Swift consumes those two published values and cannot reconstruct a matte from the Device polygon or source bounds. Alpha one is identical to the opaque Device result; alpha zero reveals the reference plate. Nearby opaque panel emission may still contribute additive halo across that boundary without creating matte.

The current panel is a fixed-pixel LCD with complete native raster, physical active width and height, derived pixel pitch/PPI, RGB or BGR stripe layout, subpixel geometry, black matrix, EOTF, black level, white luminance, native-primary chromaticities, white-point chromaticity, per-emitter angular falloff and one complete temporal-emission profile. That profile owns a bounded sinusoidal residual modulation plus a separately authored duty-cycle period, on-duration, phase and banding amount. Amount zero is exact clean emission; amount one reaches the duty-normalized pulse model without changing mean panel luminance. Current device authoring defaults to low residual flicker and zero visible banding. Residual flicker and duty-cycle emission are frame-global because the current camera has no rolling readout; this panel model cannot create spatial shutter bands. PPI and pixel pitch are derived from native raster and active dimensions and cannot contradict them. The primary-normalization matrix is solved from the declared white point, so device RGB `[1,1,1]` reproduces both that chromaticity and `white_level_nits`; no independent channel-gain authority may contradict them. Validation rejects non-finite or ill-conditioned primary matrices, non-positive primary scales, singular Bradford cone responses and unbounded final transform coefficients before an evaluator can exist. Native emission is converted through XYZ with chromatic adaptation to the ACEScg D60 basis only after channel-dependent optical evaluation. Temporal gain is integrated analytically for each shutter/motion interval and multiplies emissive radiance inside the shared optical evaluator. It neither creates another optical route nor modulates environment reflection.

Every physical Composite sample evaluates the same native panel geometry. Resolution is decided independently for every rendered pixel from its complete per-channel sensor/aperture footprint. Resolved structure uses deterministic 4x4 sensor-pixel quadrature and evaluates native stripe position. When that footprint cannot resolve individual stripes, Panel analytically integrates the periodic emitter and black-matrix mask over the footprint at its exact device-cell phase. Complete cell periods converge to the declared channel average, while fractional periods retain phase variation so the sensor lattice may produce physical spatial aliasing and moire instead of an ideal uniform replacement. Device content independently uses a deterministic separable area integral of the piecewise-constant native raster for each aperture footprint. A double-precision summed-area representation is built once per source frame, so every rectangular content integral has bounded constant sampling cost independent of its covered pixel count without overflowing on finite float source values. No interpolated signal may vary between a device pixel's subpixels. Diagnostic views change presentation and inspection only; they never substitute another panel model.

Panel spatial uniformity is a separate Panel-owned phase after subpixel radiance and before light spread. It consumes `subpixel-radiance-v1` and publishes `uniform-panel-radiance-v1` without changing color domain, alpha, raster or placement. Each Device preset explicitly owns one fixed field description: a zero-mean broad center-to-edge residual, deterministic band-limited mid/fine luminance residuals and small opponent-color residuals correlated with the same cell/backlight structures. Their scales are physical millimetres and their authored seed is stable, so the pattern is attached to the manufactured panel rather than to the camera, source raster or frame. Signal drive changes only residual amplitude, representing level-dependent LCD mura; it does not animate or choose another field. Character zero is exact identity, one uses the preset calibration and values through four extrapolate the same frequencies while validated positive gains preserve finite emission. The professional ASUS preset represents post-compensation residuals rather than an uncompensated consumer panel. Because the minimum uniformity scale is materially wider than calibrated light-spread and Device-emission-glow supports, those later filters reuse the central optical footprint's gain; this declared scale-separation approximation avoids reevaluating an effectively constant manufacturing field for every micrometre-scale tap.

Panel Structure exposes one Panel-owned `Contraste de estructura` control. It scales the explicit fixed-pixel carrier and black-matrix structure relative to continuous emission and therefore changes how distinctly the physical pixel structure is resolved. Because that structure is sampled by the camera, changing it may also physically alter the resulting moiré; it is not itself a moiré look control and does not change panel white luminance. The later Lens and Projection phase separately exposes `Intensidad de moiré`, `Saturación del moiré` and `Suavizado antialias`. Lens defines its complete sampled-interference residual as the difference between the calibrated aperture-integrated periodic panel response and a continuous-emitter reconstruction evaluated through the same projection with the same soft Device glow. Intensity scales only that residual without changing the canonical Panel Structure checkpoint: zero removes the periodic carrier from the camera path, one preserves the calibrated optical result and values above one exaggerate it. Thus Panel Structure remains available for direct phase inspection and controls the physical carrier seen whenever moiré intensity is nonzero, while total suppression deliberately removes that carrier from the later camera result rather than allowing it to alias again in Sensor. Saturation scales only the residual's chroma around preserved ACEScg luminance, and antialias enlarges the centered sensor integration support before panel and environment sampling. Antialias zero preserves the exact resolved optical footprint; positive values suppress interference and legitimate detail at the same spatial frequencies. None of these Lens controls rewrites the authored panel structure.

The native-shell physical-frame slice also exposes this same panel as one flat orthographic
surface before any camera exists. `PlacedFeederSignal` is the closed Panel input: it carries only
placed nonlinear Device RGB plus its scalar alpha sidecar and placement result. No Panel or later
phase can re-enter decoded or ACEScg source pixels. Draft, Medium and High retain the requested raster and evaluate
one, four and sixteen nested area samples per output pixel. Native expands only the sample lattice
to three by three output samples per authored device pixel: the horizontal axis resolves RGB/BGR
stripes and both axes preserve black-matrix phase. Every quality covers the identical complete
active-area UV domain. Content uses the existing placement and piecewise-constant area integral;
panel emission uses the existing EOTF, colorimetry and periodic stripe/matrix evaluator. Native is
therefore a higher-precision evaluation of the same surface, not a new panel model or framing path.

Emission and subpixel-geometry amounts are independent continuous parameters owned by the Rust
evaluator. Panel evaluation always begins from `placed-feeder-signal-v1`; source ACEScg is available
only to the Origin checkpoint. Emission zero removes panel emission rather than revealing source
pixels, while geometry zero retains continuous post-EOTF panel emission. RGB/BGR remains one
discrete topology value and is never color-mixed.

Bundled device presets currently describe LCD geometry, a reference operating white and one default optical-cover preset. They do not claim OLED or MicroLED emission and cannot label the LCD evaluator as another panel technology. A preset is an authoring template rather than a runtime profile reference; selection copies its values and the copied white and cover remain editable.

`screen-panel` ends after the emissive LCD surface, its fixed spatial-uniformity profile and its calibrated light-spread profile. Geometry then resolves the camera/screen relationship and ideal incidence rays as a typed data checkpoint. `screen-cover` owns the next physical boundary: thickness and refractive index, RGB absorption, exact unpolarized dielectric Fresnel reflection, anti-reflective efficiency, residual GGX roughness, haze, fixed anti-glare microtexture and reflected authored environment radiance. The display-cover preset family uses the calibrated matte anti-glare category as its reference anchor. Glossy and semi-gloss profiles reduce surface roughness, haze and microtexture slope monotonically from that anchor; heavy matte increases the same quantities without changing the evaluator or treating thickness, refractive index and AR efficiency as one shared scalar. Thick glossy glass remains a separate transmissive construction rather than another point on that surface-finish scale. The microtexture is an achromatic integrable cover-local height field built from deterministic random cellular heights at multiple physical scales and described by RMS slope, correlation length in micrometres, anisotropy and an explicit stable seed. Its zero-to-four Character control is exact identity at zero and never reuses the screen-space MIS scramble. The physical ray footprint filters its resolved mean slope while unresolved covariance remains in the residual GGX lobe, so one reflection remains continuous rather than becoming independent luminous points. The resolved cellular field modulates only the cover-local visible microfacet population around unit mean; it does not displace the mean GGX reflection direction. Transmitted panel emission uses the macroscopic interface and the Cover-owned haze/absorption BTDF, so the reflection can granulate without behaving like a bump map or embossing the displayed image. Application evaluates cover transmission and reflection for every spatial and emitter-channel ray before lens character; it never uses a central post-process sample. After material transmission and reflection, the same owner applies a bounded VFX emission glow in physical cover-space millimetres. The evaluator applies a soft panel-white-relative luminance key independently to each already resolved, placed, alpha-attenuated and light-spread panel-emission sample before filtering it through a positive multiscale approximation of one exponential halo with an authored physical radius. The original emission is preserved and the keyed soft contribution is added without a tap lattice or hard rectangular edge; keying before blur prevents averaged dark structure from producing a broad white stain while preserving hue. Character zero bypasses exactly; one uses preset calibration and larger bounded values extrapolate creatively. The additive result creates bloom inside the Device and diffuse RGB with zero matte beyond the projected active-panel boundary when its support remains inside the camera gate. Outside the physical cover rectangle only transmitted panel glow remains: incident-environment reflection is multiplied by the antialiased physical-cover coverage. The camera checkpoint therefore carries additive linear RGB beyond the Device silhouette without resizing the sensor frame, and reference composition preserves that RGB instead of clipping it to the Device polygon. The following lens stage may change aperture footprint, focus and chromatic projection without changing ownership of the already-authored material response. Beer absorption uses the refracted angle inside the material. Roughness and haze redistribute the bounded procedural source toward its own approximate spherical mean without creating radiance. The current model is a bounded tristimulus approximation; it does not claim wavelength-resolved thin-film interference, polarization or multi-bounce internal ghosting. Diagnostic emission views remain before the cover, while Composite and Camera Result consume it.

The current analytic library provides Uniform Neutral, Studio Softboxes, Calibration Grid, Office Ceiling, Daylight Window, Warm Practicals and Mixed Production. The image-backed source is a separate typed incident-radiance provider, not another reflection algorithm. Media owns EXR decoding, Color owns the explicit source-to-ACEScg transform, `screen-cover` owns the rough-interface integration semantics, and the Platform adapter executes the same prepared operation without inventing another model. The host retains one immutable exact single-level 2:1 texture and passes only its opaque physical view. Cover and environment character amounts are multiplicative authoring controls: zero cover is an exact identity, zero environment contributes no reflection and values above one deliberately exaggerate the current material response.

The emission-glow bright pass is evaluated before finite-panel support coverage attenuates its filtered result. Reversing that order would make valid additive exterior RGB disappear at the active outline even though the authored blur support still overlaps emitting panel pixels. `Spill exterior` is interpolated continuously against the resolved matte, so it does not change interior RGB, the bright-pass key, radius or alpha: zero removes only outside additive RGB, one preserves calibration and higher values make the same tail visible farther from the outline.

Panel character uses the same diagnostic convention inside the authoritative spatial evaluator. At
zero, continuous native emission is sampled without black-matrix or subpixel structure; at one, the
authored physical pixel layout is evaluated; values through the certified diagnostic range
extrapolate the difference. CPU and Metal implement the same interpolation after panel EOTF, so
changing the amount cannot create a second panel route.

Illumination of external scene geometry by the panel is a later scene-renderer responsibility. It must consume the already-evaluated panel as a physical rectangular area emitter, including its spatial signal and angular response. A presentation-space halo or edge glow is not an acceptable substitute. Cover-internal edge losses and reflections remain part of `screen-cover`; emitted light falling on surrounding objects belongs outside it.

Internal emission and composition use linear float values. Negative and above-one values remain valid until an explicit display or output transform permits clipping or quantization.

Color owns the explicit recording-output transform after the camera-rendered linear ACEScg boundary. The iPhone HEIC transform is selected only by stable id `iphone-heic-display-p3-srgb-full-v2`; it produces the strict `recording-output-signal-v2` artifact as exact nonlinear RGBA float with P3-D65 primaries, the Display P3 sRGB transfer, RGB matrix identity, full range and opaque alpha before codec quantization or chroma subsampling. ImageIO receives those exact Display P3 RGB codes and owns their conversion to the HEIC item's YCbCr representation and codec signaling; a BT.709 transfer tag on the encoded YCbCr item never changes the RGB input transfer contract. It is independent of the Preview ODT, and neither a filename nor a media extension may select it.

Recording Output is cumulative and Color does not encode or select codec behavior. After decoding, the adapter uses the exact inverse Color transform only to return the accepted decoded signal to the normal Preview path.

The separate Native-output catalog also provides ProRes 4444 and ProRes 4444 XQ VFX masters. Color owns the stable Log/Gamut catalog and the exact ACEScg-to-selected-encoding processor; Camera may supply only an optional recommendation id. The authored selection remains independent of Camera and is frozen together with the codec in each output job. A VFX Log/Gamut master has no display ODT and cannot be tagged or interpreted as Rec.709 by inference. The current contract does not label ProRes as ACEScg or ACES2065-1; those scene-linear interchange choices are explicit OpenEXR outputs.

Photometric calibration uses authored achromatic device-signal codes, the current panel EOTF and declared physical black/white luminance. Tests require a known uniform device code to preserve the EOTF ratio through the optical evaluator, require shutter integration and optical ND to preserve their analytic lux-second ratios, require the sensor to quantize a known exposure without changing its physical full-well decision, and require explicit camera development to place its authored middle-gray exposure. A processed handset photograph is never a luminance authority because its exposure automation and computational development are unknown; it may be used only as a later perceptual reference.

The developed camera result enters `screen-color` as immutable linear ACEScg. Camera output selection uses one stable application identifier resolved against the pinned bundled configuration. The current catalog is ACES 2.0 sRGB SDR 100 nit, Rec.709 SDR 100 nit and Rec.2100 PQ 1000 nit. Preview and export must consume the same resolved output processor; the active monitor never selects or substitutes a transform. Selecting another output does not recompute sensor capture, demosaic, white balance or the authoritative ACEScg result. Scene-linear output is a separate explicit encoding boundary, not an OCIO display-transform fallback.

The direct panel term exists only inside the antialiased active-panel coverage. The Device emission
glow receives only the already-resolved, placed and alpha-attenuated panel emission and applies a
bounded four-lobe Gaussian VFX filter above an authored panel-white threshold. It contributes bloom
inside the Device and additive RGB with zero matte outside the active outline. Every filter support
is intersected with the finite Device domain before placement is evaluated, so Fill/Crop or another
placement can never extend the emitter. Original feeder/source pixels, the reference plate,
Environment radiance and an undiffused panel copy are forbidden exterior contributions.

Native level-zero publication crosses one presentation-only backend contract after this immutable
ACEScg result. That backend must resolve the selected pinned OCIO processor and produce the final
RGBA8 bytes; it cannot own a color choice or physical operation. The current macOS product uses one
mandatory OCIO-generated Metal implementation and quantizes in the same compute dispatch. It has no
CPU product route or fallback. The pinned CPU processor is a test oracle only; maximum permitted
final-output deviation is one 8-bit code value per channel and no more than 0.5% differing channels
over the current adversarial conformance matrix.

## Physical Device outline
<!-- decision-owner: device.physical-corner-radius -->

The Device outline is a physical rounded rectangle defined by one uniform corner radius in metres. The radius is bounded from zero through half the smaller active dimension; zero is exact rectangular identity. Panel emission, source alpha, matte, cover support, light spread and glow all consume that same finite outline before projection. Setup may draw the same outline diagnostically but cannot introduce a presentation-only mask.
