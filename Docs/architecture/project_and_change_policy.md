# Project and current-contract policy

Status: normative.

The current schema version is 19. The source document requires one named Input Transform. The simulation request requires one independently authored Output Signal resolved by `screen-color`. The device document requires one stable Panel-owned Color Mode interpretation and carries the complete materialized optical-cover profile, including its required nested anti-glare microtexture realization and glow kernel, fixed spatial-uniformity profile and temporal-emission profile in addition to the LCD profile. The microtexture block explicitly stores character strength, RMS slope, physical correlation length in micrometers, anisotropy and stable seed; none may be supplied by a preset or inferred during opening. The current shot document carries the complete authored synthetic-HDR environment profile, including its required spherical-pattern identity, explicit X/Y rotations and ACEScg radiance values. Bundled device, cover and environment ids are non-authoritative authoring provenance only; normal opening and evaluation never consult those catalogs.

The portable project is a `.screensim` package directory with one strict root manifest and separate owner documents for sources, device profiles, camera/screen tracks and simulation shots. SQLite is not a project format.

The current package root is `project.json`. It references exactly one source document, device document, camera document, sensor document, screen document and shot document through portable relative paths. Each document carries its one exact schema name and version. The source document references its packaged media resource separately; no resource path may overlap a document path. Creation writes a complete package to a private sibling staging directory and publishes it by one rename only after every document and the source resource have been written. It never overwrites an existing package.

Project documents contain portable relative references and stable opaque ids. Machine-specific media associations, recent projects, window state, decoded frames, thumbnails and GPU caches live outside the project and are never authoritative. A missing external association is visible and is never replaced by a same-name or nearby file.

Normal open validates without writing. Each document has one current schema and version. Unknown versions, unknown fields, missing required values and invalid references fail explicitly.

The workstation scene shelf is separate from the portable `.screensim` project. Its current `ScreenSimulation.SavedScene.v3` records live under Application Support and reference content-addressed source, Environment and reference assets rather than arbitrary machine paths. Its media timing stores frame-rate numerator and denominator explicitly. A normal scene-library load accepts only that exact current contract and is byte-for-byte read-only. A missing Device-source asset is represented by the contract's explicit `MEDIA MISSING` state using the raster, timing and interpretation already persisted in that record; it is not a compatibility reader, filename inference or substitute asset. Missing Environment and reference identities remain errors. When the scene contract advances, the named `scripts/migrate_scene_library_v1_v2_to_v3.py` maintenance migration operates only on an explicitly selected library copy, materializes every newly required value from authoritative prior data, validates all hashes and records, and publishes the complete new library atomically. The application never keeps the old reader as a fallback and never infers a missing value during Open.

The authored Recording selection is mandatory: exact codec profile id and finite Character. Application resolves the one Color-owned recording-output transform required by that profile; persistence cannot author a contradictory pair. Profile identity is never inferred from filename, extension, container, export format or raster values. Capture presets provide only the explicit initial recommendation for new authoring and never alter a persisted selection while opening.

Current camera intrinsics require the bounded lens veiling-glare fraction. It is
materialized authoring data like every other lens coefficient; a preset id can never supply it at
open or evaluation time.

Persistence validates document structure, stable opaque identifiers including full per-track keyframe uniqueness, portable paths, exact-time representation, ordering and cross-document references. Device documents carry the complete native raster and active physical dimensions in addition to native-primary and white-point chromaticities, angular response, residual-flicker period/amplitude/phase and optional analytic-banding period/duty/phase/amount. A bundled preset id may be recorded only as non-authoritative provenance; opening and evaluation consume the complete device document and never consult the catalog. Camera intrinsics documents carry every authored lens coefficient, emitter transmission, vignetting parameter and center/edge softness in micrometers explicitly; lens preset identity is likewise non-authoritative workstation provenance and never replaces those values. Sensor documents carry the native photosite raster, saturation exposure in lux-seconds, complete current photosite response, calibrated crosstalk and nonrecursive overflow-transfer profile and exact global/rolling-shutter contract; shots reference that sensor and author the deterministic noise seed, optical ND, EI with its calibrated reference middle-gray exposure, explicit native-sensor white-balance gains, develop push/pull and one stable camera-output-transform identifier. Persistence validates their strict representation but does not resolve the transform catalog. The composition root translates them once into `screen-camera` and `screen-color` values; an unknown output identifier fails instead of selecting a display default. Persistence does not evaluate media, color, panel response, lens invertibility, camera projection, sensor response or simulation. The composition root performs one strict current-document translation into the owning domain types and validates those types before evaluation; those domains remain authoritative for their semantics.

During development, contract, profiles, fixtures, tests and renderer form one current world. A breaking change updates them together and may change every visual result. No earlier reader, evaluator, profile behavior, output result, alias, compatibility flag or version dispatch remains active.

When conversion is useful, an explicit one-way maintenance command operates on a disposable copy or explicitly selected package, writes the complete current representation and validates it. It is not callable from normal open/read/render paths. Once the current data has been updated, temporary conversion code is removed from the delivered runtime.

Build commit, OCIO library/config versions, GPU backend and project content hash may be recorded as provenance. Provenance never selects an earlier implementation.
