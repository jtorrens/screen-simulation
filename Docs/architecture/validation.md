# Architecture validation

Status: normative.

Architecture is enforced rather than inferred from prose. `architecture/domains.json` is the exact current workspace package and local-dependency matrix. `architecture/validation-owners.json` assigns every repository path to one validation owner. An undeclared package, dependency or path is an error.

Domain isolation is compiler-first. Rust crate dependencies and Swift target dependencies are the executable authority for which imports can exist. Core and Application targets cannot depend on host, UI, Platform implementation or OFX targets. Presentation targets depend only on presentation contracts and host UI frameworks; granting a Color, Media, Panel, Geometry, Camera, Sensor, Persistence or native-bridge dependency to a presentation target is an architecture failure. Source scanning is used only for invariants that the language dependency graph cannot express.

Model-authoring contract coverage requires unique stable phase and parameter ids, explicit versioned input/output artifact kinds, finite ordered scalar bounds and explicit units. Device preset coverage requires a nonempty unique set of Color Mode ids, an authored default contained in that set and finite ordered luminance capability containing its reference value. Simulation-request coverage proves the selected Color Mode belongs to the selected Device capability and White Luminance lies inside its range without mutating the preset. Host-conformance coverage evaluates the same resolved request through complete-frame and partitioned render windows and declares temporal input requirements explicitly. Adapter-specific GPU tests remain adapter tests and cannot make that backend a core dependency.

Test-authoring coverage requires `Origin`, `Feeder Output`, `Device Mapping and Interpretation`, `Panel Structure`, `Panel Light Spread`, `Relative Geometry`, `Cover and Environment`, `Cover-glass Glow`, `Lens and Projection`, `Exposure and Shutter`, `Computational Capture`, `Sensor Bloom`, `Sensor and CFA`, `Sensor Noise` and `Develop and Demosaic` in that exact order, with exact artifact equality at every adjacent boundary, an explicit default cumulative Preview phase and a typed Preview result for every phase. Selecting each phase must set its exact cumulative evaluator intermediate, including Origin, so stale Preview routing is impossible. Relative Geometry is a typed data checkpoint and may retain the preceding raster in Preview without fabricating a visualization. It publishes mutually exclusive Look At and Free control sets: Look At includes camera distance and orbital orientation X/Y; Free includes camera and screen translation XYZ and rotation XYZ. Mode conversion preserves the resolved pose in the forward direction and derives the Look At orbit while explicitly retargeting the screen center in the reverse direction. The ABI contribution mapping proves Geometry and Environment are independent: Geometry one with Environment zero must still project through the authored camera, while Environment one with Geometry zero cannot activate projection. Placement belongs to Feeder Output and must not appear in the Device phase. Panel Structure, Panel Light Spread, Cover, Environment, Cover-glass Glow, Lens, Shutter, Computational Capture, Sensor Bloom and Sensor Noise character own finite owner-published scalars with zero identity, calibrated physical value one and their certified maxima. Sensor and CFA publishes clean mosaiced RAW before noise; Sensor Noise publishes the same RAW identity after its authored stochastic response; Develop and Demosaic alone publishes the developed ACEScg camera artifact. Every scalar descriptor owns finite ordered input bounds, a slider step equal to five percent of that range and an explicit in-range reset value. Every choice owns an explicit valid reset id. Numeric input is range validated but is not quantized to the slider step. A display-referred Input Transform seeds an equivalent Output Signal only when Application creates a new selection; the resulting authored values are independent. Changing Device or Color Mode cannot mutate Output Signal. A Device change is one Application intent that atomically returns its preset default Color Mode, reference White Luminance, light-spread profile and cover defaults. A Camera change returns its default compatible lens; fixed cameras expose exactly that one lens while interchangeable cameras expose their declared compatible set. The host may not reconstruct dependent defaults, reset targets, camera/lens compatibility, placement choices, Preview qualities or published options.

Phase-checkpoint coverage proves that requesting an intermediate stops evaluation there even when later physical stages are enabled. Published diagnostics describe that effective stopped execution rather than later authored state: before Sensor Bloom the sensor is inactive, Sensor Bloom reports coupled clean charge, Sensor/CFA reports noise zero, Sensor Noise reports its authored amount and development is active only at Develop and Demosaic. Preview tests forbid diagnostic normalization or visibility compensation: the selected output transform may legitimately clip or conceal correct values without changing the checkpoint. Headless visual comparisons encode the selected display transform as 16-bit PNG so their smooth gradients are not reduced to eight bits; the accepted phase checkpoint remains the typed linear-float artifact rather than that presentation file.

Cover-glow validation requires exact identity at amount zero, finite calibrated and creative values, unit-sum physical kernel weights, preservation of weights and radii under deterministic aperture-dependent quadrature rotation, absence of a coherent fixed tap lattice across optical samples, and collection of panel radiance by a camera ray just outside the active device outline. CPU and Metal spatial evaluators must agree within the declared optical tolerance. Every authored analytic environment pattern and its rotation require finite output, exact zero-strength identity and CPU/Metal parity; roughness redistribution uses the owning pattern's approximate spherical mean rather than an unrelated neutral constant. An image-backed source additionally requires exact source/raster exclusivity, a finite 2:1 ACEScg raster, explicit radiometric scale and exposure, angular-diffusion-prefiltered Metal storage and the same cover-interface response as the analytic source. Level zero must equal the accepted HDR exactly; coarser levels and their residual scatter must use positive unit-sum Gaussian passes with equirectangular latitude correction, preserve uniform incident radiance, remain continuous across the seam and keep one connected response for one connected bright source. Normal incidence must remain radial; decreasing view cosine must monotonically stretch only the incidence-plane axis within its bounded represented support and without a discontinuity at the sub-texel optimization threshold. Its core and tail angular footprints must be invariant under panorama resolution, exactly sharp at zero and monotonic with roughness; haze must monotonically widen and increase only the tail contribution. Sensor-bloom validation requires exact zero identity, charge conservation except at physical sensor edges, nonrecursive full-well overflow transfer, exact full-frame versus regional equality with the complete two-photosite support halo, bit-exact parallel-gather parity with the serial charge model and invariance under worker-count changes. Reusing dead initial-charge storage for the overflow destination must retain that same bit-exact serial parity, region equality and worker-count invariance. Sensor/CFA collection validation covers all four Bayer patterns, nonzero-origin regions, clean and stochastic capture, exact selected-row matrix response, canonical raster ordering and bit-identical results across worker counts.

Lens veiling-glare validation requires exact identity at zero, bounded finite authoring, exact
projected-gate clipping, full-frame/region/rolling equality and CPU/Metal agreement. Visual matches
against photographs are evaluation evidence rather than numeric golden truth; known camera, lens
and device facts remain separate from assumed exposure, distance and unpublished calibration.

Sensor-boundary coverage supplies one identical shutter-integrated linear checkpoint to the CPU
reference route and the native macOS adapter and requires bit-identical integer RAW codes,
full-well masks and ADC-clipping masks for clean and noisy capture. A separate pre-sensor optical
tolerance may compare independently evaluated CPU and Metal exposure rasters, but it cannot be
converted into a RAW tolerance or used to authorize a second GPU sensor evaluator.
RAW publication coverage requires both clipping masks to be uploaded and published exactly;
Developed ACEScg coverage proves development consumes the same authoritative codes without
requiring an unobservable platform copy of either mask. Complete-route direct texture publication
retains the two ordered reconstruction/development passes, the documented CPU/Metal tolerance and
regional behavior, and must preserve the exact final presentation hash without an intermediate
complete developed buffer or a third publication pass.

The architecture guard also verifies that active documentation does not link into the sealed historical archive and that exact retired paths do not return. It uses Cargo metadata for real package edges rather than accepting source-text conventions.

Contract coverage will reject unknown versions, unknown fields, aliases, missing required values and invalid references. Startup coverage will prove byte-for-byte read-only project opening. Conversion coverage will use disposable copies. CPU/GPU color and numeric implementations will be compared with documented tolerances. Native output publication requires generated OCIO Metal to remain within one 8-bit code value of the pinned CPU oracle and below 0.5% differing channels over the complete adversarial matrix for every current output transform.

Source-to-feeder coverage requires every authored Input Transform to declare its reference domain, every Output Signal to resolve both its scene-rendering and display-colorimetric OCIO processors, and equal sRGB input/output to traverse ACEScg without an identity route. The strict feeder color checkpoint is RGBA16F with exact Input Transform, Output Signal, resolved processor and alpha identities. Swift and Rust readers reject unknown fields, unknown files, contradictory transform ids and incorrect raster length. Changing Device, Color Mode, White Luminance, placement or Preview quality must leave that color checkpoint byte-identical. Separate feeder-composition tests prove Fit and Fill/Crop preserve aspect, Stretch alone may deform, One-to-One maps one source pixel to one target pixel, and target Device dimensions or placement change `placed-feeder-signal-v1` without recoding the color checkpoint. Device-interpretation coverage proves matching signal/mode pairs preserve intended response and intentional mismatches change panel emission. Panel-structure coverage proves the cumulative checkpoint stops at subpixel radiance before spread, cover and camera. Diagnostic PNGs may differ by at most one 8-bit code value per channel under the existing OCIO CPU/Metal tolerance.

Desktop export coverage decodes an in-memory PNG and requires its raster and RGBA bytes to equal the immutable Native level-zero publication buffer exactly. Display-pyramid tests separately require exact 2× area reduction, including odd raster edges, so export cannot silently consume a presentation level.

Photometric coverage owns one explicit device-code scale and verifies every patch is exactly achromatic. A uniform half-code panel with zero authored black level must retain the exact authored EOTF ratio relative to white after physical optical evaluation. Separate owning-domain tests verify analytic shutter/ND scaling, photosite quantization and clipping identity, explicit middle-gray development placement, and parity between the ideal camera preview and the complete Native RAW/develop route for the same calibrated exposure. The pinned ACES 2.0 sRGB SDR output also owns fixed middle-gray and diffuse-white code anchors. No photographic file is a golden value for these tests.

Lens coverage requires unique stable template ids, nominal focal length, complete finite coefficients including physical center/edge softness, successful full-gate inversion certification for every bundled model and valid midpoint interpolation across the current catalog. Every capture template must declare a nonempty compatible-lens set containing its default. Every compatible id must resolve in the single lens catalog; a fixed association must contain only its default. Capture templates contain no duplicate focal length or aberration authority. Each distinct shifted and Y-flipped observed coordinate is inverted once; the resulting valid unscaled ideal coordinate is reused across channels, pupil samples and irradiance, while every VFX ±X/±Y coordinate retains its own validity and channel scaling acts only on a copy. A pupil sample prepares one world and screen-local lens origin for all of its channel and footprint rays; the inverse screen quaternion and VFX rim origins are shared only where their inputs are exactly identical. The ideal-point natural-vignetting and pupil-throughput weight is invariant across direct pupil samples and must be reused without changing its channel-specific value. PSF coverage requires physical softness to grow correctly with sensor sampling density, authored image height and f-number, and requires its circular quadrature to remain centered, bounded and unit-normalized. Direct-pupil coverage requires exactly 32 equal-weight aperture rays independent from every sensor-footprint and PSF sample, one stable global pupil orientation with identical CPU/Metal ray order, per-channel chromatic geometry before Sensor/CFA and CPU/Metal optical parity. The Metal product backend specializes the same owned kernel into one Thin Lens and one VFX 2D function-constant pipeline; tests require the immutable plan to select the matching pipeline, forbid a second parameter-buffer evaluator selector and retain CPU/Metal parity for zero, calibrated and exaggerated lens amounts in both evaluators. A focused chromatic edge must remain spatially coherent instead of acquiring pixel-dependent color displacement from finite pupil quadrature. The frozen cross-quality matrix requires High and Native to remain within `3e-5` maximum absolute channel difference; this convergence bound does not relax the separately declared CPU/Metal optical tolerance. Complete-frame row-prefix coverage requires fractional source-edge weights, placement clipping, negative and above-one values and wide optical footprints to remain within the existing CPU/Metal optical tolerance; a prefix representation cannot relax the tolerance or select another result. A full Lens-to-Sensor exposure invariant proves the inverse-square f-number term is applied exactly once: two stops down yields one quarter of the RAW exposure at fixed shutter and matches after four-times shutter compensation before clipping.

The VFX 2D depth-of-field approximation uses the same coherent chief-ray chromatic projection and replaces only the discrete pupil axis with one deterministic centered continuous footprint. Its VFX-only PSF combines authored softness and Airy radius by root-sum-square variance matching without changing the canonical direct-pupil thin-lens PSF. Its footprint must be exactly repeatable, collapse for a channel where that channel's authored focus plane meets the chief ray and grow continuously away from that condition without inventing a post-sensor blur or another CFA route. The sensor-pixel footprint is projected into panel UV per channel by chief rays at both sides of each sensor axis before it can combine with the pupil footprint; changing distance, angle or gate coverage must therefore change panel support through geometry rather than through a presentation-space constant. The projected sensor-pixel and pupil half-extents add independently per axis as convolution support: zero pupil extent preserves the exact projected sensor footprint and a nonzero pupil grows continuously and monotonically. For the owned vertical RGB-stripe topology, the VFX-only carrier residual samples the canonical device signal through exactly one quarter of the projected horizontal sensor-pixel half-extent and the complete projected vertical sensor-pixel half-extent at the coherent chief ray. It is multiplied only by the authored Panel Structure amount. The vertical carrier must preserve analytic black-matrix coverage rather than select a narrow phase that can miss the row margin. The carrier footprint remains independent of pupil extent. It cannot reuse the complete defocus-footprint averaged device code, alter the content envelope, change the canonical direct-pupil evaluator or move into a post-sensor stage. Sensor/CFA remains the sole owner of camera sampling, aliasing and demosaic.

Cover-glow coverage requires exact identity at zero, invariant uniform linear energy at calibrated
strength, continued collection just outside the projected active outline and CPU/Metal parity for
the centered core/tail area filters. A faster approximation cannot introduce a crop at the active
panel boundary or move the operation after Sensor/CFA.

Test focus coverage requires Autofocus to track the authored Look At distance and, in Free mode, the positive optical-axis intersection with the transformed screen plane. Parallel, rearward and out-of-domain intersections fail explicitly. Manual focus preserves its independent authored value. The Lens phase publishes Autofocus and f-number with camera-preset reset values, hides manual distance while Autofocus is active and exposes it when disabled. The Exposure phase publishes real exposure time and changing f-number or exposure time must alter the same immutable physical request consumed by interactive and reference evaluation. Exported physical settings record the focus policy and resolved distance. Every phase publishes a nonempty owner-authored perceptual summary; character header ownership is explicit and cannot be reconstructed from control ids by Swift.

Spatial Metal coverage includes a full-resolution coordinate-phase case rather than testing only
small origin-adjacent rasters. The current 8064×6048 iPhone sensor, integrated lens and 3840×2160
ASUS panel must remain within the CPU optical oracle tolerance at a non-origin resolved-subpixel
region. Spatial shader compilation must use safe math with floating-point contraction disabled in
both Cargo and packaged shader builds; phase-unstable fast math is not a supported quality level.

Optical-cover coverage requires unique stable current cover and analytic-HDR environment ids, valid complete material profiles and successful resolution of every device template's default cover id. Zero cover character must be bit-exact identity, zero environment character must contribute no reflection, IOR 1 and perfect AR must produce exact zero interface reflection even at grazing incidence, and the calibration grid must lose contrast as roughness redistributes its energy. Every analytic distribution and a nonzero rotation require CPU/Metal spatial parity under the current optical tolerance. Cover changes must affect Composite without changing the pre-cover Emitted Radiance diagnostic. Draft and Native consume the same authored cover/environment request and evaluate it over the same aperture-ray set.

The default cumulative Preview contract selects the final published phase. Native-render freshness coverage distinguishes an invalidated physical revision, the current revision rendering, a cancellation requested but not yet confirmed by the Metal worker, and a completed current physical revision. Replacing the source pattern or media frame and selecting a different cumulative physical phase must invalidate a completed Native result exactly as a physical-parameter edit does. Swift presentation must not construct a parallel source/profile identity or reject a result already validated by the physical request revision and hash. Active-worker progress is capped below 100%; terminal coverage requires the result texture to be published before the observable task lifecycle ends and the control becomes green. Cancellation coverage proves that no replacement Native job can be submitted during that confirmation interval. Viewer coverage requires a fixed one-point frame outline around the transformed raster independently of Fit scale, zoom and pan.

Broad tests are never a fallback for an unclassified change. The validation-owner manifest must first assign the changed path to its semantic owner and exact checks.
