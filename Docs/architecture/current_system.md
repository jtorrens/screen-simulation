# Current system

Status: normative.

Application owns every phase boundary as a `PhysicalArtifactId`: the typed identity proves adjacency, while host adapters receive only its stable versioned string for presentation and serialization. Swift and the native bridge cannot declare, infer or reorder artifact identities. The CPU evaluator publishes a closed `PhysicalPipelineCpuArtifact`; sensor checkpoints contain the actual integer RAW artifact and expose their normalized code/clipping image only through a separately named diagnostic presentation view. RAW, Device signal and physical radiance are never stored in a field named ACEScg.

Approximate-2D Motion Blur derives projected velocity from exact rational neighbor times around the output frame. Times before the first frame or after the last frame reach the canonical terminal camera and Device extrapolation instead of requesting an invalid negative frame identity or clamping continuous scene motion.

In the v23 Saved Scene and Queue contracts below, “tracks” means only the separately typed embedded 3D animation record. v23 does not contain or claim a generic parameter-track collection; adding one requires a new owner-published typed contract, schema revision, exact-time evaluator and validation together.

The application consumes an explicitly interpreted animated raster and evaluates a physical fixed-pixel LCD through animated screen/camera geometry and phase-preserving photosite-footprint sampling. The FFmpeg adapter accepts the video and still-image formats enabled in the one shipped decoder configuration, including H.264 and ProRes. ProRes 4444 is a recommended high-quality production source, not an input restriction. OpenEXR sequences use the explicit OpenEXR adapter. No codec or container chooses color interpretation.

The current processing chain is:

```text
media source
→ explicit pixel decode interpretation
→ decoded source frame
→ explicit Input Transform into linear ACEScg
→ independently authored feeder Output Signal transform
→ typed nonlinear feeder signal
→ feeder placement into the selected target-device raster
→ Device Color Mode interpretation
→ colorimetrically declared, angle-dependent LCD emission
→ native panel subpixel structure
→ calibrated panel light spread
→ independently animated screen/camera projection
→ explicit optical-cover transmission and authored environment reflection
→ bounded VFX emission bloom and soft halo from resolved panel emission, with additive support outside the active panel outline
→ deterministic sensor-footprint and thin-lens integration
→ immutable linear ACEScg optical result in image-plane illuminance
  ├→ explicit optical-preview or still-output transform
  └→ exact global-shutter temporal integration
     → explicit photometric exposure, optical ND and shutter integration in lux-seconds

     → single reference edge-directed Bayer demosaic

     → camera-authored rendering intent in linear ACEScg
     → explicit Color-owned recording-output transform
     → nonlinear float recording signal before quantization and subsampling
     → explicit Recording-owned encode/decode
```

Native output jobs keep codec and color encoding as separate authored choices. The current VFX movie masters are ProRes 4444 and ProRes 4444 XQ with one explicit Color-owned Log/Gamut selection. A capture preset may recommend a Log/Gamut as the initial value, but it neither restricts the catalog nor changes an existing authored choice. Application freezes the exact codec and stable Log/Gamut id in the immutable render job; the writer applies that OCIO transform and does not declare the result as Rec.709. ACEScg and ACES2065-1 remain explicit OpenEXR output contracts rather than implicit ProRes interpretations.

Every Render job freezes exactly one delivery mode, `Preview` or `Final`. Preview always composes the Saved Scene Reference behind Device plus Spill, publishes one opaque medium and may apply one optional WIP Review preset. Final never bakes Reference into its media and publishes either one combined Device-plus-Spill medium or two synchronized Device and Spill media. Every Final medium uses an implemented alpha-capable format; combined Final and Device retain the complete unassociated carrier RGB plus the physical matte as straight alpha, including RGB outside zero alpha. Separate Spill retains its independently declared physical-linear or Editorial alpha contract. Raster, Color encoding, format, pixel encoding and signal range are authored fields rather than route identities, and a Render preset only copies initial values into those fields.

Final separate delivery owns one optional Fusion Composition switch. Enabling it requires the same separate Device and Spill media, adds the package-relative `.comp` and metadata, and includes the authored external Reference only as a Loader inside the composition. It never bakes Reference into either Final medium. The composition derives its exact native Fusion input transform from the selected media Color encoding; changing a preset, encoding or format changes the frozen fields and never selects a parallel renderer. Preview forbids Fusion Composition.

The Render inspector materializes the selected Saved Scene's complete Delivery Raster as explicit width, height and placement. Those values are editable only in the render draft and every Queue job freezes one required resolved raster. Queue evaluation uses it for carrier placement, approximate-2D processing, Reference composition and output dimensions without changing the Saved Scene or consulting the visible workspace. Fusion Scene Package retains its separately owned active-resolution contract.

Before that final delivery boundary, image checkpoints remain RGB linear float in their explicitly named spaces; video/full range is not a property of those float artifacts. A selected Recording codec may temporarily encode, quantize or subsample its nonlinear recording signal, but Recording decodes that simulation back into the canonical Camera Rendered linear ACEScg checkpoint. It cannot redefine the downstream render transport.

The synthetic Source catalog includes one immutable `VFX Delivery Stress` RGBA pattern. It publishes deterministic linear ACEScg RGB plus straight linear alpha at a 3840 x 2160 raster. Its identified zones contain hard and fractional alpha, non-black RGB below zero alpha, one- and two-pixel transitions, smooth RGB/alpha ramps, AP1 primary and secondary saturation, achromatic scene-linear values from zero through 220 and one identified 224 excursion beyond the normalized ACEScct transport ceiling. `acescg` is therefore an explicit Color-owned Input Transform accepted at the same Test-authoring boundary as every catalog transform. The pattern always crosses the explicit Color, Feeder and Raster boundaries; the older RGB-only procedural device-signal route rejects it because that route cannot transport its alpha. The pattern is test evidence only; selecting it never changes an output contract.

Reference is a host-owned input boundary after the physical Device result, never an input to panel, optics, sensor, recording codec or Fusion radiometry. A Saved Scene records exactly one selected Reference plate: its explicit external reference video/image, `Damero VFX`, black, white or middle gray. The selected video remains an exact decoded, explicitly interpreted frame and controls the workstation timeline only while it is selected; synthetic plates are generated directly as opaque linear ACEScg delivery-raster frames. Setup, Native result presentation and a Render Queue job configured as `Device + referencia` request this same selected plate from one Reference provider and compose exactly `DeviceRGB + plateRGB × (1 − physicalMatte)`. Delivery Raster therefore publishes its authored output frame and the transported physical occlusion matte as separately typed artifacts. Recording Output and Recording Codec transform only RGB and carry that matte beside the encoded signal; neither an opaque Delivery background nor an opaque recording format may replace it with output alpha. The Queue freezes the Reference selection with its Saved Scene authoring. The provider does not project, grade, infer an alpha interpretation or alter the physical Device result. Fusion Scene Package keeps its separate explicit external reference Loader contract and never uses this provider as a radiometric input.

Preview owns the complete opaque `Reference + Device + Spill` composition and never publishes a transparent alternative. Final owns either one transparent `Device + Spill` medium or two synchronized `Device` and `Spill` media. Single-media Final consumes the transparent Delivery Raster before any opaque presentation composite and writes its complete additive RGB without association changes plus the independent physical Device matte as declared straight alpha. RGB remains present where alpha is zero. The two-media contract owns one directory and exact per-frame or per-movie manifests. Physical-linear separation retains complete Delivery RGB in Device with the transported fractional matte and publishes opaque-black Spill as exactly `DeliveryRGB × (1 − matte)`, preserving exact physical reconstruction without dividing by alpha. Editorial separation instead retains that same complete encoded Device, preserves the full black-subtracted encoded exterior RGB residual and writes uniform straight alpha 0.125 into Spill. The editor's alpha-aware Add supplies the deliberate attenuation without scaling the stored RGB signal. Both media use the same format, color encoding, cadence, range and raster, and audio is forbidden.

`Editorial` is a Render preset, never a delivery mode or renderer. Applying it copies Final, separate Device/Spill, ProRes 4444 XQ RGB Full Range, ACEScct/AP1, no audio or WIP Review, approximate-2D Motion Blur and `Editorial Add · alpha 12,5%` into the editable draft. Every copied field may then be edited independently. ACEScct/AP1 is scene-referred interchange without an ODT. Rec.709 is instead the complete ACES 2.0 display transform from ACEScg to D65 Rec.709 BT.1886 at 100 nits, using display `Rec.1886 Rec.709 - Display` and view `ACES 2.0 - SDR 100 nits (Rec.709)`; it is never a color-space-only conversion. Device remains the complete output-encoded carrier with the physical matte in alpha. Spill stores full encoded residual RGB and uniform straight alpha 0.125. At 100% alpha-aware Add in editorial it therefore reproduces the Resolve-tested reduced contribution without scaling RGB or asking the editor to set clip opacity. It deliberately does not claim exact reconstruction, preserve negative physical residuals or commute with display transforms.

Every standard Render job freezes exactly one Motion Blur mode: `disabled`, `physical` or `approximate-2d`. Disabled resolves one temporal sample and preserves the existing output route byte for byte. Physical retains the authored shutter interval and performs normal physical temporal integration with the frozen sample count. Approximate 2D performs exactly one physical evaluation at frame time, then applies one deterministic screen-space shutter pass to the linear ACEScg Delivery carrier RGB and its independent physical matte together. The pass treats RGB as an additive carrier rather than alpha-associated color, so RGB outside zero matte is retained. Device and Spill are derived only after this pass: Device remains the complete carrier with straight physical matte. Physical-linear Spill remains `carrier × (1 − matte)`, preserving exact scene-linear reconstruction; the separately owned Editorial Add mode instead derives its declared encoded-domain approximation after the selected output transform. Reference composition remains later and is never blurred. Fusion Scene Package forbids this standard-output mode and retains its independently reconstructed Fusion motion blur. Approximate 2D is explicitly non-physical: it does not claim disocclusion, temporal parallax or reflection reconstruction, or physical shutter integration.

A display/output-encoded Preview may additionally freeze one WIP Review preset from its own Global Library family. The preset owns the exact WIP output color space, host output raster, placement/resampling, canvas, blanking, typography, outline, shadow, padding, timing and six identified text zones. WIP is forbidden for Final and scene-linear Preview media. Preview is already an opaque `Reference + Device + Spill` deliverable. Application applies the selected output transform, sends that opaque frame through the exact bundled `com.jtorrens.WIPReviewProbe` OFX effect using Metal, verifies an opaque result and then invokes the writer. One host process, plugin scan, OFX instance, command queue and pair of shared Metal buffers remain alive for the complete output attempt; frames and their current literal calculated fields cross one bounded binary pipe protocol without temporary raster files. The adapter is a Metal-only OFX host and loads the bundle itself; it neither links nor copies the plugin renderer implementation, never claims to be Fusion and has no CPU retry. App-calculated fields are resolved per output attempt, then concatenated with the authored free-text prefix and sent as literal text while the OFX calculated-field parameter is `None`. `File Name` resolves from the frozen authored destination, including the authored free version suffix. The job snapshot contains the complete preset, so library edits cannot alter an in-flight or historical attempt.

Final separate delivery owns one optional `Fusion Composition` package. It evaluates the immutable Saved Scene through the normal headless Camera Rendered ACEScg route; Preview, Reference and the ideal Source are not radiometric inputs. Application publishes two typed frontal artifacts from resolved Device carrier geometry rather than testing alpha: Device retains its complete fractional occlusion matte. Physical-linear Spill is additive RGB over opaque black and its RGB sum with Device is exactly the physical result. Editorial Add instead publishes the separately owned encoded-domain approximation with straight alpha 0.125. Both media share one selected color encoding and one selected implemented alpha-capable format. Every Color encoding with an exact native Fusion inverse is available independently of format; applying a Render preset copies both values once and retains no dynamic preset dependency. The writer encodes the selected contract into OpenEXR, TIFF, ProRes 4444 or ProRes 4444 XQ. With `<stem> = <name><version>`, sequences are `media/<stem>_Device%08d.<ext>` and `media/<stem>_Spill%08d.<ext>`; movies omit the frame token. The comp and schema-v2 metadata use the same stem and remain package-relative, while an external Reference retains its authored absolute path.

Each Device and Spill Loader declares exact range, length, channel and alpha interpretation. Each branch then applies the exact native Fusion 21 transform from its actual delivery encoding to ACEScg. ACES output encodings and supported camera Log/Gamut encodings use `AcesTransform`; DCM colorimetric encodings and DaVinci Intermediate/Wide Gamut use native `ColorSpaceTransform` with explicit input gamut/gamma, ACES AP1 linear output, and tone and gamut mapping set to none. No OCIO node, configuration path, LUT or copied OCIO resource exists in the composition, and no preset is silently replaced by another color space or format. Device is one RGBA medium in every selected format that supports alpha: its physical occlusion matte remains embedded in A through its single ImagePlane3D and Renderer3D branch. Physical-linear Spill is already opaque. Editorial Add Spill keeps alpha 0.125 in its movie and is added over opaque black inside the comp to set only its plane alpha to one without scaling RGB; either result then travels through its own ImagePlane3D and Renderer3D branch. Both projected branches use 32-bit-float OpenGL texture depth; there is no `DeviceRGBOpaque`, `DeviceMatteOpaque`, separate matte carrier, matte Renderer3D or matte-recombination node. Projected Spill is added to projected Device RGB while Device A is preserved unchanged, then the authored SynthEyes `DE4RadialStandardDegree4` distortion is applied to that RGBA result. Brown k3, tangential terms or shifted optical center reject creation; there is no STMap or substitute route. Final `Custom` math is exactly `resultRGB = deviceRGB + spillRGB + plateRGB × (1 − deviceA)` and never conventional Over.

An ACES 2.0 Rec.709 D65 100 nit Reference uses native `AcesTransform` `IDT_REC709_100_INV_ODT` to `ODT_ACESCG`; an unrepresentable authored Reference transform emits that same named node disabled with `PassThrough = true` and preserves the original id. Every job-specific Sticky Note lists Device, Spill, Reference and metadata paths; exact encoding and scene/display character; alpha interpretation; exact transforms into ACEScg; the working space and formula; and the manual Viewer `IDT_ACESCG` to `ODT_REC709_100` contract with no gamut compression and Pre-Divide/Post-Multiply enabled. It documents but cannot persist Fusion Viewer UI state.

Every multi-file output owns one directory below the selected output directory; a single-file output writes the selected file directly. Collision validation occurs before the immutable job enters the queue. An existing single file or any file contained recursively by a sequence/package directory requires an explicit cancel-or-replace decision; an absent directory or a directory containing only empty subdirectories does not. The frozen policy is exactly `FailIfExists` or `ReplaceGeneratedFiles`. Replacement authorizes only the job's declared generated-file manifest and never clears or recursively replaces the destination directory.

Every arrow is a typed boundary. A consumer receives a complete validated result and never reconstructs the prior owner's semantics. Declared media color metadata crosses the Media boundary as typed evidence only. YUV matrix and signal range resolve independently from the Input Transform. Initial import of any decodable source or reference preserves every unambiguous detected value and completes only absent interpretation fields with disclosed editable product defaults: sRGB encoded Rec.709 Input Transform; Y′CbCr, BT.709 and video range for movies; RGB and full range for stills; Premultiplied when alpha is present and its association is absent; Ignore/Opaque when alpha is absent. Before decoding, the workstation identifies every field that did not come unambiguously from metadata. These defaults become the initial authored selection and may be changed immediately; they are never relabelled as detected evidence. Reopening a Saved Scene or evaluating a Queue attempt uses its persisted authored interpretation and never reruns import defaults. RGB sources bypass the YUV interpretation route, and monochrome sources require range but not matrix. The Platform adapter receives only a fully resolved decode interpretation and configures the single FFmpeg YUV-to-RGB conversion before OCIO.

It stores one stable identity per selected profile family, only explicit fixed overrides and parameter tracks; a manual edit creates an override and Reset removes it. Values without an override come from the current internal Device, Cover Glass, camera, lens or other selected definition whenever Application materializes the scene. It contains exact current frame and rational frame rate, Viewer fit/zoom/pan and either the exact synthetic-pattern identity or absolute paths for external source media. Source media, reference media and an external HDRI are the only external dependencies. Imported camera animation, point clouds and geometry are embedded scene authoring and never retain an importer-file dependency. Scene records, thumbnails and their strict index live in `~/Library/Application Support/SCREEN-SIMULATION/Library/Scenes`. A generated reflection environment is owned by exactly one saved scene and has the stable identity `scene-<scene-id>.exr`: editing the reflection rig overwrites that one map and updates its generated identity, never appends a new map. Duplicating a scene copies the generated map into a new scene-owned identity; deleting the scene removes it. The unsaved working state has one separate `working-reflections.exr`. Opening verifies each permitted external path, loads external HDRI and reference media to completion, and only then publishes the authored scene. A thumbnail, filename or nearby file can never impersonate an unavailable source, and a missing selected internal profile id fails explicitly. Rename changes only the shelf label. Duplicate creates an independent scene and resource ownership. Update and Delete require confirmation; Open also requires confirmation because it replaces the active scene. The normal scene reader accepts only the current schema and never converts on startup. A later schema revision requires an explicitly selected, one-way maintenance migration that produces and validates the complete new scene library before the new reader opens it. A saved-scene contextual Render command only selects that scene and navigates to the Render page. If that scene is active and differs from its stored authoring, the workstation requires an explicit Update before enqueueing; an unsaved working state cannot enter the queue. The Render page alone places an editable Render inspector below Scene Library; its first group authors destination directory, scene-seeded name and free version suffix, followed by Preview or Final mode, delivery topology, Spill mode, range, editable preset-seeded raster/color/format fields and the explicit disabled, physical or approximate-2D Motion Blur mode. Only its `Añadir a Render Queue` action validates collisions and freezes the settings and exact manifest. Preview always bakes Reference + Device + Spill into one result and may enable WIP Review. Final never bakes Reference: it publishes Device + Spill combined or as two alpha-bearing media. Separated Final may additionally write a Fusion composition that includes Reference and converts the selected delivery encoding back to ACEScg; this switch is not a third output type. Physical Motion Blur replaces only the immutable job's shutter temporal-sample count while preserving the saved shutter interval and animated camera, Device and emission. Disabled and approximate-2D modes each perform one physical evaluation; only approximate 2D applies its later Delivery-carrier pass. Preview samples the saved reference at the same exact frame time and composites it only after the camera-rendered checkpoint, saved Delivery Raster and any approximate-2D pass, so reference pixels can never enter a physical phase or blur pass. The native output queue is a separate narrow controller: each job owns an immutable value copy of the Saved Scene ids, overrides, tracks and resources plus any scene-owned generated Environment bytes and output configuration. At the start of each attempt, its isolated workspace resolves the current defaults for exactly those stored ids once and freezes the materialized attempt; later shelf edits never enter it, while a later requeue may observe updated defaults for the same ids. It also owns sequential execution, progress, cancellation and terminal state. `WorkspaceModel` prepares the job but cannot own or reinterpret the queue lifecycle.

The SynthEyes Fusion importer translates one ASCII `.comp` into the same internal 3D authoring contract used by the scene; after import, the file has no identity or runtime role. The floating `Tracking 3D` panel requires explicit camera and point-group selection, exposes point-cloud and auxiliary-geometry visibility independently, and lets each auxiliary mesh be hidden separately. The user authors one positive metres-per-SynthEyes-unit scale; Geometry applies it uniformly to camera translation, point cloud, auxiliary meshes and the position of a Device already anchored in that world, while the Device's physical dimensions remain metres. Until scale succeeds, neither the camera nor geometry enters the physical request. A resolved animated camera drives the same Free camera pose, focal length, physical gate and distortion used by every renderer at the current frame. Application projects the diagnostic 3D primitives through that resolved camera and its active sensor window, then applies the same Delivery Raster placement and preview extent as the image beneath them; the tracking plate raster remains media metadata and never replaces the render camera raster. Importing the Fusion camera clears prior lens shift and distortion, then authors its typed DE4 radial-degree-four calibration; a missing or all-zero calibration is exact pinhole and an unknown or contradictory model is rejected. Polygon faces retain their authored cardinality, so quads remain quads at the import and Viewer boundaries and are triangulated only internally when a renderer requires triangles. Saved Scene embeds the complete camera curves, point cloud and geometry together with role selections, visibility and the direct metres-per-unit scale; no importer file is consulted by Save, Open or render.

The current Test descriptor publishes twenty-three ordered cumulative phases. `Origin` ends at the versioned linear-ACEScg raster. `Source Adjustment` consumes that exact raster and applies authored exposure, contrast, saturation, temperature and tint in extended scene-linear ACEScg while preserving alpha and values outside zero to one. `Feeder Output` consumes that exact graded artifact, applies one independently authored Output Signal transform and places the resulting signal into the selected target Device raster with explicit Fit, Fill/Crop, Stretch or One-to-One semantics. Fit and Fill/Crop are mathematically identical when source and target have the same aspect ratio; the placement identity remains distinct and no artificial difference is introduced. A new selection is seeded from an equivalent display-referred Input Transform when one exists and is thereafter authoritative and independent. The strict nonlinear RGBA16F color checkpoint names the Input Transform, Output Signal and resolved feeder processor; it is the immutable input to placement, while the phase publishes the placed feeder-signal artifact. `Device Mapping and Interpretation` consumes that artifact and interprets its codes through the selected Device Color Mode, EOTF and editable White Luminance. The device's internal scaler is identity in the current version because the feeder already delivers the selected native raster; a future non-identity device scaler requires its own explicit model and phase. Changing Color Mode cannot recode the feeder color checkpoint. `Panel Structure` applies native subpixels and black matrix. `Panel Uniformity` then applies the Device-owned fixed manufacturing and compensation residual in physical panel coordinates; its map is signal-dependent but remains invariant under camera, placement and frame time. `Panel Light Spread` consumes that accepted uniform-panel-radiance artifact and applies the Device-owned calibrated spread profile. `Panel Temporal` consumes only `spread-panel-radiance-v1`, analytically integrates the resolved emission over the authored capture interval and publishes `temporally-integrated-panel-radiance-v1`. `Relative Geometry` consumes only that temporal checkpoint and resolves the selected camera, the independent camera/screen transforms and their physical separation as a typed data checkpoint without inventing a display raster. Its `Look At` mode authors camera distance and orbital orientation X/Y around the screen while always targeting the screen center; its `Free` mode authors camera and screen translation XYZ and rotation XYZ independently. Switching modes converts the current resolved pose instead of jumping to an unrelated seed. `Cover and Environment` consumes that geometry to evaluate incidence, transmission and reflection. `Device Emission Glow` consumes only the already resolved, placed and alpha-attenuated panel emission. It applies a bounded four-lobe separable-Gaussian VFX filter above an authored panel-white threshold, adds bloom inside the Device and publishes additive RGB with zero matte outside the active outline. Its millimetre radii follow camera projection; it never reads the original source, reference plate or Environment and never preserves sharp subpixel structure in the exterior halo. `Lens and Projection` selects one camera-compatible objective and applies the explicit Autofocus/manual policy, resolved focus distance, authored f-number, projection and its complete physical approximation. `Exposure and Shutter` integrates the image-plane illuminance over the authored exposure time, shutter behavior and ND. The same physical duration is presented as an editable shutter angle at the effective project cadence and as its synchronized reciprocal speed in `1/s`; neither representation is a second exposure authority. `Computational Capture` consumes that canonical integrated exposure and materializes an explicit bracket before Sensor. One exposure is exact single-capture identity; two to eight exposures add successively shorter highlight-protection captures at the authored EV spacing. The current VFX approximation evaluates optics once and represents the bracket as aggregate sensor capacity, so exposure count does not multiply optical render cost. It never applies a hue-specific look or tone curve. `Photosite/CFA Collection and Noise` consumes that effective exposure, selects the authored Bayer channel and publishes deterministic collected charge with shot/dark noise plus deferred read noise. `Sensor Bloom` consumes only that collected charge and publishes coupled charge after calibrated four-neighbour crosstalk and nonrecursive overflow transfer. `Sensor Readout and RAW` consumes only the coupled charge and applies full-well clipping, read noise, analog gain and ADC quantization to publish the final noisy mosaiced RAW. `Develop and Demosaic` consumes that RAW and publishes the developed linear ACEScg camera result. `Camera Rendering Intent` consumes only that accepted result and applies the selected capture preset values for exposure, contrast, saturation, temperature and tint to publish the final linear ACEScg camera-rendered artifact. It cannot alter RAW, choose an output transform or encode a recording. `Device VFX Transparency` consumes that accepted camera result together with the alpha sidecar transported from placed feeder signal. It publishes `device-vfx-composite-v1` as premultiplied additive Device RGB plus its occlusion matte; `ignore` resolves full physical Device coverage and `device-transparency` uses authored source alpha for the complete Device, including emission, pixel structure, moiré, cover, reflection, glow and optics. Reference composition consumes this contract directly as `DeviceRGB + plateRGB × (1 − matte)` and never reconstructs visibility in Swift. `Delivery Raster` consumes that exact artifact. `Recording Output` consumes the accepted delivery artifact and applies the Color-owned transform required by the selected recording profile to publish `recording-output-signal-v2`. It remains an explicit diagnostic checkpoint, not a second normal authoring choice. `Recording Codec` consumes only the RGB signal and the authored Recording profile/character, performs one real independently coded encode/decode round trip for each requested frame and publishes `decoded-recording-signal-v1` plus exact encoded-byte count and payload hash. The physical occlusion matte is a separate non-color artifact: it bypasses recording quantization and chroma subsampling unchanged and is reattached after decoding. An opaque recording profile therefore cannot turn exterior zero-matte pixels into opaque black, and additive RGB remains valid where the reattached matte is zero. The reference plate never enters this recording round trip; final reference composition remains `DecodedDeviceRGB + plateRGB × (1 − physicalMatte)`. Recording Codec has no GOP, B-frame, lookahead or whole-clip state. H.264 uses Rec.709; HEVC Main10, ProRes 422 HQ and ProRes 4444 use the Color-owned Rec.2100 PQ signal and return through its exact inverse to linear ACEScg. Every capture preset explicitly declares its usual recording profiles and one default; Application marks those as habitual while still offering the complete codec catalog. Selecting another camera changes the default profile but never hides the other profiles. The decoded result is transformed back to linear ACEScg and shown through the same independent monitor Preview transform as the camera result. Sensor dynamic range remains owned by capture/exposure/develop; recording authoring does not expose a generic SDR/HDR switch or display a log signal unless that look is already present in the photographed source content. Codec-only changes reuse the accepted physical checkpoint; Output changes invalidate both downstream artifacts; upstream authoring invalidates all three. Application/Rust publishes all controls, effect summaries, header-control ownership, options, limits, slider steps, reset targets and the convention `0 = no effect`, `1 = calibrated physical` and `>1 = creative extrapolation` only where applicable. Every numeric slider spans twenty equal logical steps without visual tick marks while its adjacent numeric input accepts any in-range value; reset restores the owning preset default or the explicit seed for non-preset authoring. Character remains editable in the card header when its details are collapsed; Swift does not identify character fields or write phase summaries. The host renders each phase as an aligned expandable card and offers the same ordered phase identities in `Ver hasta`; selecting any phase sets its exact cumulative evaluator intermediate, including the explicit Origin checkpoint. The independent Preview ODT follows the inspected result. A checkpoint that lies outside that ODT's representable range remains authoritative even when its Preview clips or hides values; presentation never introduces an artificial normalization or visibility transform.

The current environment model publishes neutral, studio-softbox, calibration-grid, office-ceiling, daylight-window, warm-practical and mixed-production analytic linear-ACEScg patterns and an exclusive image-backed equirectangular source port identified as `environment-image`. The latter requires one finite exact single-level 2:1 ACEScg radiance texture plus explicit source-unit radiance, exposure EV and panel-local X/Y rotation. Test authoring exposes both rotations and exposure independently from the linear creative Environment character multiplier; selecting a procedural source releases the image source explicitly. Rough image reflection is integrated directly from that source with view-dependent GGX visible normals, dielectric Fresnel and Smith masking; deterministic multiple-importance sampling combines the GGX distribution with a solid-angle-weighted luminance distribution prepared from the exact source. The private distribution hierarchy contains sampling weights only: reflected radiance is always fetched from the unchanged level-zero map. It never substitutes an angular blur pyramid, fitted halo or analytic source. Device Emission Glow keys each accepted Panel Light Spread emission sample by panel-relative luminance before filtering, then evaluates one smooth multiscale approximation of an exponential halo with one authored physical radius. It preserves the original emission and adds only the keyed soft RGB contribution inside and beyond the active panel outline while leaving the matte unchanged. Its explicit `Spill exterior` control multiplies only additive RGB as the resolved Device matte falls away: zero removes external spill, one preserves calibration, and values through four make the same smooth tail perceptibly longer without changing its radius, key, interior bloom or matte.

Computational Capture represents its bracket as aggregate sensor capacity plus `floor(log2(exposure count) × Character)` effective fused-quantization bits, capped at sixteen. The effective precision belongs to the combined result and does not redefine the sensor preset's physical ADC; exposure count still does not multiply optical render cost.

The Sensor Bloom card exposes the selected camera preset's neighbour-crosstalk fraction and nonrecursive overflow-transfer fraction. They remain Sensor-owned physical parameters, resets restore that preset's exact authored values, and changing the camera replaces both atomically with the newly selected profile.

Media sample selection consumes exact project time and one authored policy. Rational timestamps compare by value even when the project and stream use different denominators. `Exact` requires an equal presentation timestamp and does not extend source edges. `Floor` selects the latest timestamped frame that does not exceed project time; `Nearest` compares the adjacent timestamps exactly and selects the earlier sample on a tie. Both non-exact policies explicitly hold the first or last sample when global-shutter evaluation crosses the edge of a bounded source. Missing timestamps and unknown-duration access beyond the exact initial sample fail explicitly. There is no implicit policy change, retry, loop mode or legacy sampling route.

A new Test selection starts `Ver hasta` at the final phase published by Application. The physical request owns one parameter revision and hash; adopting another source raster or frame, changing its interpretation or placement, selecting another cumulative physical phase, or editing a physical parameter invalidates its completed frame through that single authority. Swift does not reconstruct or compare a second request identity for presentation. Native progress never presents 100% while the worker remains active: the host publishes the validated result texture and ends the observable task lifecycle before presenting the green current state.

## Technology

The current macOS-first implementation uses Rust 1.97.1 behind the SwiftUI/AppKit composition root in `apps/screen-native-macos`. Native RAW development runs through the required Metal backend on Apple Silicon; the physical core and typed domain boundaries remain platform-independent, but the current version does not require, ship or validate a Windows/D3D12 adapter. Native display publication uses one required Metal backend generated from the pinned OCIO processor and quantizes its result directly to RGBA8; the OCIO CPU processor remains only a numeric oracle with the explicit tolerance in `native_compute.md`. A Native cancellation remains an active job until the Metal worker confirms the cancelled terminal state; the host exposes that interval as `Cancelling`, retains progress from the last completed tile and cannot submit another Native job meanwhile. Media has two capability-selected Platform adapters: AVFoundation for media it declares playable and one bundled FFmpeg configuration for a codec AVFoundation declares unsupported. Both return the same decoded RGB contract after the persisted source matrix/range has been resolved; neither chooses an Input Transform or introduces an alternate Color route. The product color implementation is the extractable `packages/StudioColor` boundary copied from the authoritative CREDITOS-HDR OCIO/ACES implementation at the pinned source commit and hashes. The native host authors an explicit Input Transform into linear ACEScg, resolves the independently selected Output Signal into the nonlinear feeder contract, applies the Device Color Mode only in panel interpretation, calls the Rust-owned physical evaluator once per immutable request and uses the StudioColor OCIO-generated Metal display processor for preview and output. The local packager builds only `dist/Screen Simulation Native.app`, bundles and validates the complete FFmpeg dylib closure under `Contents/Frameworks` with app-local rpaths, and validates the current physical ABI. There is no packaged Rust/Slint product, runtime backend selector or compatibility shell.

The product's physical-frame boundary is the versioned coarse ABI in
`ScreenPhysicalBridge.h`, specified by `Docs/NATIVE_PHYSICAL_FRAME_CONTRACT.md`.
It carries one selected frame through an opaque input containing the source
linear-ACEScg texture, the nonlinear Device RGB texture resolved by StudioColor
and one explicit raster-placement policy. An immutable resolved Device snapshot
then crosses ordered Screen and Capture domains to one opaque linear-ACEScg
result texture. Screen consumes Device RGB and placement; Capture consumes the
physical Screen result. Rust/Metal owns physical stage semantics; Swift owns
only request orchestration and presentation state.
Preview, ColorSync, DeckLink and render output transforms remain downstream of
this boundary and cannot appear as physical contributions.

The current supported system is Apple Silicon on macOS 14 or later. Windows and D3D12 are outside the current version and impose no parity requirement on Metal work.

## Current scope

`Delivery Raster` follows Device VFX Transparency and precedes Recording Output. It consumes `device-vfx-composite-v1` and publishes `delivery-acescg-raster-v1`, preserving scene-linear ACEScg while establishing explicit output width, height, aspect-preserving `Fit`, aspect-preserving centered `Fill / Crop`, or centered `1:1` placement, and transparent or black background. Application publishes the explicit UHD, DCI 4K, HD, DCI 2K, vertical, square and current-camera-raster presets. Selecting one materializes all of its values; editing any delivery dimension, placement or background changes the authored identity to `custom` without inferring a preset from matching values. It never changes gate, lens, sensor, exposure or camera look. Recording Output and Codec consume only this accepted delivery artifact, so delivery-only or codec-only edits reuse the camera checkpoint.

Every Test phase publishes its native calculation-domain label for `Ver hasta`. The visible image remains a presentation of that authoritative checkpoint through the explicitly selected Preview ODT; the label never claims that the monitor directly displays native linear, radiometric, charge or RAW values.

Capture presets publish exact `Full`, `Half` and `Quarter` raster modes. `Half` denotes approximately half the total photosite count rather than halving each axis. The selected mode becomes the effective sensor raster before physical evaluation without changing gate dimensions or lens geometry. Every capture preset publishes the continuous `VFX 2D DOF` footprint as its explicit default Lens evaluation model. Selecting any capture preset atomically restores that default, while `Lens and Projection` exposes the resolved model as authored state instead of inferring it from quality, resolution or camera identity during evaluation. Direct `Thin Lens` remains available only as an explicit authored selection. The iPhone 16e defaults to 5712×4284 `Half`; ARRI ALEXA 35 defaults to 4608×3164 `Full`.

The project-owned physical state includes complete LCD, optical-cover, environment and sensor profiles. Cover and environment cross the same immutable Application request as panel and sensor; they are not workstation-only effects.

The current implementation target is one source clip per simulation shot, one authored rational project frame rate, one project-owned complete LCD profile and sensor profile, internally authored independent camera-transform, camera-intrinsics and screen-transform tracks, an RGB/BGR stripe panel, transformed physical projection, deterministic reference sampling, a public linear optical result, exact global-shutter integration with analytically integrated frame-global panel emission, mosaiced RAW capture, debug views and still export. The immutable physical request also carries a typed host render context: complete-raster dimensions, a bounded render window, exact rational X/Y render scale and exact rational pixel aspect. The present evaluator explicitly supports only the complete window at unit scale with square pixels; other valid contexts fail as unsupported instead of selecting a different route or being silently ignored. The technical desktop also authors seven explicit bundled test sources: an animated checkerboard, a static black-on-white eye chart, a 3840×2160 editorial page containing common document/UI text sizes, a 3840×2160 photographic camera-color reference containing diverse skin tones, textiles, neutrals, glossy/matte materials and fine texture, a deterministic 3840×2160 frequency reference containing a Siemens star, authored 1–8-pixel line pairs, slanted edges, channel ramps and exact pixel marks, a procedural photometric scale containing nine achromatic device-signal patches at exact codes `0.00`, `0.05`, `0.10`, `0.18`, `0.25`, `0.50`, `0.75`, `0.90` and `1.00`, and the exact 3840×2160 ASUS framebuffer photographed in the controlled iPhone VFX comparison, including browser chrome and authored page scroll. That VFX source explicitly selects `OneToOne`, so one source pixel reaches the matching ASUS device pixel without the invalid enlargement of the earlier cropped raster. Their device-signal channels remain in `[0,1]`; none is a media fallback. The four raster references are decoded once into the same prepared device-signal representation used by media, while every procedural reference enters the same device-signal, placement, panel, optical and native-capture evaluator without an image-decoding route. A source whose raster differs from the device native raster requires one authored placement policy: `Fit`, `FillCrop`, `Stretch`, or `OneToOne`. Pixel decode matrix, pixel decode range, source IDT and alpha association are independent explicit decisions. Alpha association is resolved before panel evaluation, while its scalar value remains a non-color placed-feeder sidecar for the independently authored Device VFX Alpha Mode.

The technical desktop camera-result view authors one complete capture profile: native photosite raster, physical gate, Bayer pattern, sensor response/noise/ADC data, one lens-association policy, one explicit default lens id and a nonempty compatible-lens set. The bundled templates are seed records for the workstation Global Library: ARRI ALEXA 35 Open Gate, an explicitly labelled calibrated approximation of the iPhone 16e main camera, and explicitly labelled reference approximations for Canon PowerShot A470 plus iPhone 14 Pro main and ultra-wide validation cases. Every optic, including an integrated handset module, lives in the same typed Global Library lens family. Fixed cameras declare only their matching integrated/reference lens and do not emulate computational photography. Application resolves the selected Camera and compatible Lens identities from one Global Library snapshot and materializes their separate complete values before evaluation; physical phases never resolve a profile id. Focal length, distortion, chromatic behavior, vignetting, transmission, softness and veiling-glare fraction come only from the selected lens, never from a duplicate camera field. Reference approximations expose unpublished geometry, full-well and radiometry as assumptions rather than calibrated facts.

Within `Lens and Projection`, the micrometric PSF core and the wide-field veiling-glare tail are
separate authored quantities. The current tail redistributes a bounded fraction toward the covered
panel's gate-average linear irradiance before exposure. It is not cover-glass glow, sensor bloom or
a field-dependent ghost model.

An explicit one-frame native capture may evaluate either the complete sensor or a centered native 1024×1024 region. Both use the same optical, RAW and development route. Evaluation is partitioned into 128-pixel sensor tiles without first materializing a giant luminous-panel raster. Every ray retains complete-sensor coordinates, and media is decoded and cached at every exact temporal sample requested by that tile rather than frozen at nominal frame time. The panel signal remains at its native device resolution with one immutable summed-area representation per resolved media sample. Sensor CFA phase, counter-based noise identity and panel-cell phase are therefore global: a regional result is exactly the same pixels as the corresponding crop of a complete capture. Demosaic evaluates its complete three-photosite support around each requested region before cropping it, so tile boundaries cannot create another result. Tile execution occurs off the UI thread, reports progress, supports cancellation between complete tiles and publishes the authoritative frame only after completion; the host samples progress at no more than 20 Hz and republishes observable values only when they change, so technical UI observation cannot contend with Native computation. A downscaled staging visualization may expose completed tiles without becoming an output. The worker also derives a deterministic three-level 2× area-filtered display pyramid from the completed developed frame. The workstation viewer selects among that pyramid and the unchanged native level according to magnification: Fit cannot resample the full sensor texture directly, while `1:1 Sensor` presents the native level at one sensor sample per logical viewer pixel. These display levels are non-authoritative and cannot become capture or export data. The neutral-gray viewer draws one fixed one-point outline around the exact displayed raster after Fit, zoom and pan, so the frame boundary remains distinguishable from its surround. Zoom and pan never change camera geometry, focus, optical sampling or the authored result. Physical inspection remains a separate camera operation and is unavailable as a substitute for viewer magnification in the camera-result view.

The workstation has one explicit quality selector: `Draft` targets a 360-pixel-wide preview, `Medium` 960 pixels and `High` 1920 pixels; `Native 1024 px sensor crop` and `Native complete frame` select exact sensor capture. The final discrete preview width may differ from its quality target by one pixel so the integer height and width represent the authored viewport within the required half-pixel bound. The three preview qualities use the identical camera, lens, depth-of-field, panel and full-gate projection; only the explicit output sampling raster differs. In optical diagnostic views they use the explicit presentation-only Preview EV. In Camera Result they instead approximate the authored capture exposure and ODT while explicitly omitting the sensor/RAW stages enumerated by the sensor-capture contract. They never change the selected view. Ray projection continues to use the exact authored viewport aspect and the viewer presents that aspect, so this is raster quantization rather than another camera or gate policy. A larger mismatch remains an error. While one preview is running, UI changes invalidate its publication and coalesce into one subsequent render at the selected quality instead of creating parallel semantic routes. Native modes never render implicitly: one contextual `Render` button appears beside the fixed quality and camera selectors, and cancellation remains explicit. A completed non-stale Native result may be exported as one output-transformed 8-bit RGBA PNG by encoding its unchanged level-zero publication buffer. Export neither reevaluates the scene nor consumes a display-pyramid level, and its selected output transform is named in the workstation result. That display-referred still remains distinct from the Render Queue's explicit scene-linear ACEScg OpenEXR contracts and cannot be used as their input.

The phase picker retains the ordered physical stages in their execution order. Panel and lens
amounts use the same authoring convention as cover and environment: zero is the corresponding ideal
identity, one is the calibrated profile and values above one deliberately extrapolate character.
These amounts are parameters of the same CPU/Metal optical request and invalidate Native results;
they do not select alternate renderers. CFA and demosaic remain discrete because a continuous amount
would not describe a physical operation. Intermediate-buffer taps are intentionally not claimed until
the current immutable results expose those boundaries.

Panel Structure owns `Contraste de estructura`, which controls how strongly the explicit fixed-pixel carrier and black-matrix structure differs from continuous panel emission. Lens and Projection separately owns periodic-versus-continuous sampled-interference intensity, residual-chroma saturation and optical antialiasing. At zero intensity Lens removes that low-frequency interference while preserving the visible fixed-pixel carrier, spread and glow from the accepted Panel Structure chain; at one it preserves the calibrated sampled result. These controls cannot act as a source grade or change panel white luminance.

The bundled LCD definitions are seed records for the workstation Global Library Device family. Device records have stable ids, native raster, active physical dimensions, one uniform physical corner radius, one reference operating white with an explicit basis label and one default Cover Glass identity. Locked seed records and user-created records follow the same lookup, override and materialization route. Application resolves the selected Device and Cover Glass identities from one Global Library snapshot, applies explicit scene overrides and freezes both complete profiles into the evaluation request; physical evaluation never looks up a preset id. A Saved Scene without an override follows an edited current Global Library value, while a portable materialized project retains its complete embedded profile independently. Generic seed records state that their white is an authored approximation; the ASUS ProArt PA329CV uses its published 350-nit typical SDR value and the 14.2-inch MacBook Pro seed uses its published 500-nit SDR value. `Custom` edits the same complete values and does not select another evaluator. PPI, diagonal and pixel pitch are derived presentation values, never independent authorities.

The optical-cover catalog provides glossy, semi-gloss, matte and thick-glass approximations. Its complete material profile authors thickness, refractive index, anti-reflective efficiency, RGB absorption, roughness and haze. A separate environment source supplies either one analytic distribution or one equirectangular HDR radiance raster. Values are scene-linear and may exceed one; EXR decode does not choose color, and the authored Input Transform converts the decoded samples to ACEScg before the physical request. Image-backed radiance has an explicit cd/m²-per-source-unit calibration and exposure in stops. The desktop exposes independent non-negative character amounts: cover amount zero is an exact identity and environment amount zero contributes no reflection, while values above one explicitly exaggerate the same operators. Cover evaluation is shared by Draft, Medium, High and Native capture.

Point cloud, auxiliary tracking geometry, centres and labels form one persistent diagnostic overlay pass owned by Application. It consumes the same immutable `ResolvedSceneFrame`, active sensor window and Delivery Raster placement as the image beneath it, carries the same revision/frame/time identity and may be drawn over every render quality; the host only draws returned 2D primitives and cannot project tracking geometry itself. Changing metres per SynthEyes unit scales camera translation, point cloud, auxiliary geometry and an already anchored Device about the common imported origin while Device dimensions remain physical metres, so its projected anchor cannot drift.

Interactive tracking-world scale publishes successive complete resolved scene frames while the gesture is active. Each publication contains the updated imported-camera scale and Device anchor together, so its diagnostic overlay remains visible and carries the same identity. Ending the gesture records Undo but cannot rematerialize a different scale or change the last visible result.

The native macOS workspace has exactly three primary pages in this order: `Escena`, `Render` and `Settings`. `Escena` contains the scene library, physical authoring inspector and Viewer. `Render` contains the same scene library and the Render Queue as its sole work panel; it has no second Output tab, contextual output inspector or Viewer. `Settings` owns the general Application output preset/ODT controls, Output inspector and Viewer-presentation information together with the existing Library and Monitor settings. Queue navigation never mutates the active scene or its published Viewer result. Returning to `Escena` refreshes presentation descriptors without selecting or evaluating a diagnostic phase, then republishes the result already owned by the active Setup or physical quality. A cached physical foreground is recomposed only through the existing Reference provider, so a video or synthetic Reference remains visible after visiting Render or Settings.

The main window title is the exact current library name of the active Saved Scene and falls back to `SCREEN-SIMULATION` only when no saved scene is active. The active scene card has one amber outline in every Scene Library presentation. Double-clicking its thumbnail invokes the same Open intent as its contextual command. Opening another scene is immediate when the active scene still equals its stored snapshot; when it differs, one decision boundary offers Save, Discard or Cancel before the existing transactional Open. Save updates the active scene and then opens the target, Discard leaves the stored active scene unchanged and opens the target, and Cancel performs neither operation. Reopening the already active scene is a no-op.

An Application failure presented by the native workstation uses one blocking detail surface with a short human explanation and a selectable technical payload. The payload includes the failed boundary or operation and the stable identifiers required to reproduce a rejected request whenever they are available. It supports ordinary text selection and `Cmd-C` plus an explicit copy action; a bridge error without its host-side operation context is not a complete user-facing diagnostic.

## Test inspector hierarchy
<!-- decision-owner: ui.test-inspector-hierarchy -->

Application publishes one explicit inspector group and nested section location for every editable physical control. The macOS presentation renders those locations and cannot infer grouping from phase ids, control ids, labels, prefixes or physical execution order. Host-owned Source acquisition and Reference controls may be inserted only into stable Application-published section slots; they cannot reorder or relabel model controls.

The top-level Test inspector order is `General`, `Referencia`, `Device en escena`, `Entorno`, `Cámara`, then `Raster de entrega`. `General` contains Application-published quick-control references and `Referencia` remains the host-owned reference boundary. Every other nested subcard contains controls from exactly one physical phase; a phase that currently owns more than one domain may publish separate owner-facing sections, but a section never combines controls from different phases. `Device en escena` contains Source adjustment, VFX transparency, feeder, individual panel stages, Device geometry, glass and Device glow. `Entorno` owns the environment-facing subset of the current cover/environment phase. `Cámara` contains camera geometry, lens/projection, exposure/shutter, the individual sensor stages, computational capture, camera rendering intent and codec. These presentation groups do not change phase adjacency, artifact ownership or evaluator order.

Every primary card and nested section uses one full-width disclosure header. Pressing anywhere on the header toggles it, and its chevron is always at the trailing edge and rotates to express expansion. `General` begins expanded; every other primary card and every nested section begins collapsed. Controls are rendered only inside the expanded body; an interactive control cannot be nested inside the disclosure button.

## Native action-control states
<!-- decision-owner: ui.native-action-state -->

Native controls that represent a persistent enabled mode use one presentation contract throughout the workstation: active is the application amber accent, available but inactive is secondary gray, and unavailable is disabled and cannot be invoked. The state describes the action's effect, not whether a utility window happens to remain open. Momentary commands retain normal platform presentation, while progress, success, warning and failure colors remain status semantics rather than active-state colors. A capability-backed action is unavailable when its required runtime resource is absent; in particular Monitor is disabled unless a DeckLink device with a selectable output mode has been detected.

Applying an interactive authoring mode commits its scene intents and republishes the currently selected Setup-family diagnostic immediately from the updated scene. It cannot wait for the user to leave and re-enter that mode to reveal the committed result.

## WIP Review and render derivation
<!-- decision-owner: output.wip-review-presets -->
<!-- decision-owner: output.render-rerender-and-versioning -->

WIP Review is an optional Preview-only opaque editorial-output boundary, so Preview alpha is exactly `Ignore/Opaque`. Preview first composes Reference + Device + Spill and preserves already additive RGB without multiplying it by the physical matte. WIP conversion occurs only after that canonical Preview composition and cannot alter Final Device/Spill media, Fusion media or their independent physical matte. The narrow OFX host advertises only Metal, creates one process and OFX instance for the complete attempt, reuses its shared Metal image buffers and command queue for every frame, waits for that queue and rejects a non-opaque result. A bounded binary pipe carries current frame pixels and parameters directly; no per-frame process, plugin scan, instance construction or temporary raster file exists. It has no CPU publication, fallback or retry route.

A Preview job may freeze one complete WIP Review preset from its own Global Library family when its selected output is display/output encoded. The preset owns output color space, host output raster, placement/resampling, canvas, blanking, typography, outline, shadow, padding, timing and six identified text zones. Rec.709 Gamma 2.4, Rec.2100 PQ and Rec.2100 HLG resolve to their exact pinned ACES output transforms and writer signaling before the OFX boundary; HDR is never used to infer PQ versus HLG. WIP is forbidden for Final and scene-linear Preview media. Application sends the opaque final composed Preview frame to the exact bundled `com.jtorrens.WIPReviewProbe` OFX effect through its Metal render action after that output transform and before the writer. The adapter loads the bundle itself; it neither links nor copies the plugin renderer implementation and never claims to be Fusion. App-calculated fields are resolved per attempt, concatenated with authored free text and sent literally while the OFX calculated-field parameter is `None`. `File Name` resolves from the frozen authored destination, including its free version suffix. The immutable job stores the complete preset snapshot.

The first Render-inspector group authors an explicit destination directory, output base name and free version suffix. Selecting a Saved Scene seeds its name and does not invent a version. Movies use `directory/name+version.extension`; sequences use `directory/name+version+frame.extension`. Separate delivery inserts the stable `_Device` and `_Spill` role suffixes before the frame number or extension, and Fusion uses the same authored stem for its package and contents. Terminal jobs — completed, failed or cancelled — expose `Volver a renderizar esta versión`, which loads the historical scene/output/WIP snapshots and the exact directory, name and version into the editable Render-page inspector, and `Renderizar la escena actual…`, which loads the current saved scene with the prior output choices and output identity plus the current WIP record of the same stable id. Neither action creates a job or reads unsaved editor state. Only `Añadir a Render Queue` freezes a new linked job. If its exact manifest already exists, adding offers only Cancel or manifest-limited Overwrite; there is no inferred or automatically incremented version. Every pending job also reinspects its complete output manifest immediately before it becomes `rendering`, because files may have appeared after enqueue or may have been produced by an earlier queued job. A newly found collision blocks evaluation and requests Cancel or manifest-limited Overwrite; accepting Overwrite is persisted into that immutable attempt before any graph or frame work begins. The writer may then remove only the declared colliding files and never unrelated directory content. The originating job remains unchanged and each derived job records its origin UUID.

The active Render Queue row publishes transient elapsed wall time from attempt start and, after one completed output frame, an approximate remaining duration derived from the attempt's observed average completed-frame cost. Neither value is persisted or changes evaluation. Cancelling requests cancellation from the active physical job, retains its borrowed inputs and textures until the worker reaches a terminal state, then records the queue job as cancelled; it never terminates the application or publishes a partial frame.

Clearing terminal Render Queue records removes completed, failed and cancelled records together. Pending and actively rendering records are the only states retained by that operation.

Device interpretation applies the selected EOTF and authored-alpha attenuation once per placed Device sample before publishing linear Panel emission. Geometry integrates that accepted premultiplied linear artifact; neither a projected footprint nor its carrier/detail branch may average nonlinear Device codes and apply EOTF or alpha again. The deterministic Panel Uniformity field is invariant under camera and Device motion, while its filtered gain, subpixel stripe coverage and black-matrix coverage retain the exact support of each moving projected footprint.
